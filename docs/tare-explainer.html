Tare

the weight of the box, subtracted, so you know what's actually inside.

Tare is an old scale-house word. Put a bowl of flour on a kitchen scale and it weighs the bowl too — so you press "tare," the scale remembers the bowl's weight, and subtracts it. What's left is the flour, and only the flour.

Crypto does the opposite trick, usually by accident. A "vault" that holds your deposit can quietly hold it by way of a second vault, which holds it by way of a third. Nobody subtracts the boxes. Tare does — it opens every box a position sits inside, all the way down, and tells you what's actually there.

why this exists

A "vault" in DeFi is just a pool that invests your deposit for you. Nothing stops it from investing in another vault.

That second vault can invest in a third, and that one in a fourth. Each one is a completely ordinary, working piece of software — nobody did anything wrong. But each one also reports its own size to the world, and each one counts the vault beneath it as part of that size. The same hundred real dollars gets weighed again, fully, at every single layer.

So a portfolio that looks spread across four different protocols can, once you actually walk down through it, turn out to rest on a single underlying pool. From the outside it looks diversified. It isn't. Nobody can see this today, because every protocol publishes its own data in its own shape — there's no common layer that lets you cross from one vault's data into the next one's and keep walking.

A similar project at a previous ETHGlobal hackathon built the easier 90% of this: given a protocol, it could report what that protocol held. It said outright that the harder half — given one specific account, what does it actually hold once you follow the shares all the way down — was still unbuilt. That's the gap this project fills.

what tare actually gives you

Five plain answers, computed from real chain data.

01

The full unwrap

Follow a position through every layer of wrapping and land on the real assets sitting at the bottom.

02

One honest number

The effective collateral multiple — how many dollars of claims are stacked on top of every real dollar. 3.4× is not diversification, it's the same dollar counted four times.

03

Cycles, named

Sometimes vault A ends up indirectly owning a slice of itself. That's flagged as a finding — not hidden, not crashed on.

04

Alerts that arrive on time

If a risk setting changes anywhere beneath a tracked position, you hear about it within the same block — not five minutes later, after a poll.

05

Ask it plainly

Query the whole thing in ordinary English instead of a query language. The words go to a model; every number still comes from deterministic code.

how it works

Four layers, stacked. Each hands the next something more useful than raw chain data.

Read the bold sentence in each layer for what it does. The line beneath it is how — skip it on a first pass, it'll be here when you're ready.

01

Normalization

Every protocol ships its own data shape. This layer translates all of them into one shape.

A standardized module for ERC-4626 flows — deposits, withdrawals, share-price evolution, underlying-asset references — authored properly against The Graph's standardized subgraph products and deployed across two or more networks, so the fan-out has something real to fan out to.

02

Resolution — this is the product

Give it a wallet or a vault. It walks down through every layer of wrapping, stops at real assets, and hands back one clear number.

The traversal engine follows share tokens hop by hop, calls convertToAssets at each layer, detects cycles with an active-path check plus a strongly-connected-components pass, and computes the effective collateral multiple. Anything it can't finish becomes a distinct, typed partial result — never a guess dressed as an answer.

03

Monitoring

It doesn't just check once. It watches every layer beneath a tracked position and tells you immediately when something changes.

A Substreams subscription, reorg-safe — it rewinds on a blockUndoSignal rather than ever treating an undo as a trigger — with a resumable cursor and replay deduplication by chain, block hash, transaction hash, and log index.

04

Interface

You don't need to know any of the above to use it. Ask a question in plain English; get back the number, the evidence, and the gaps.

An MCP server exposes resolution as callable tools. A language model selects tools and explains findings — but every amount, traversal, and eligibility decision is produced by deterministic code beneath it, never invented by the model.

under the hood

The four decisions that make the resolver trustworthy instead of merely plausible.

Cycles are findings, not bugs

Vault A can end up owning a slice of itself through B. Most systems would call that an infinite loop and crash. This one calls it what it is — rehypothecation — and reports the exact path.

Two mechanisms run together: an active-path set that halts traversal the instant the current path repeats a node, and a strongly-connected-components pass over the whole observed graph that groups and explains every cycle, including ones not on the primary walk. A node reached by two independent parents is a shared dependency, not a cycle — the two are kept distinct.

Precision compounds

Every layer rounds a little. Four layers of rounding can quietly add up to a real error if nobody's careful about it.

Every raw quantity is kept as a bigint with its native decimals preserved, and each hop's convertToAssets output is cached by chain, block, vault, method, and input — never as a rounded price-per-share, because conversions can be non-linear and integer rounding at one hop shouldn't get compounded silently by the next.

What counts as "the bottom"

Not every token is a real bottom. A stablecoin is. A liquid-staking token or an LP token might just be another wrapper wearing a different name.

The leaf policy: plain ERC-20 assets qualify as terminal. An ERC-4626 token is traversed further when a supported adapter exists for it. Anything else — LP tokens, liquid-staking tokens, bridge receipts — becomes an explicit opaque node rather than a false leaf. This policy is published, not assumed.

A result can be honestly incomplete

If one piece of data is missing, the tool doesn't paper over it with a guess. It shows exactly what it does and doesn't know — and the code itself won't let it pretend otherwise.

A partial resolution and a complete one are different types, not different values of the same type. A function that prints a headline multiple can only accept the complete, verified type as input — the compiler refuses to compile code that tries to hand it a partial graph. This is what "the type system should have prevented you from claiming it" means in practice:

type Resolution = | { kind: "complete"; graph: CompleteExposureGraph ; coverage: CompleteCoverage; verification: VerificationResult } | { kind: "partial"; graph: ObservedExposureGraph ; gaps: readonly [ResolutionGap, ...ResolutionGap[]]; coverage: PartialCoverage } type MultipleResult = | { kind: "available"; value: DecimalString; evidence: MetricEvidence } | { kind: "unavailable"; reasons: readonly MetricBlocker[] }
how you'd check its work

Don't take its word for it. Check it against a second, independent source.

For the deepest test position, the leaf holding is read twice: once through the subgraph (The Graph), and once by calling the chain directly over RPC — at the identical block number, so both reads describe the same instant. The two numbers are printed side by side. If they disagree beyond a documented tolerance, that's reported as a mismatch, not smoothed over.

RunWhat it demonstratesExpected result
Deep A real 3+ layer position, walked to the bottom Cycle checked, multiple computed, leaf verified by RPC
Control The simplest possible position — one layer, nothing hidden Resolves to exactly 1.0×, no cycle
Degraded A data source is down mid-run Reports incomplete coverage — never a confident wrong number
  • Never fabricate a number. If a value has no writer, the interface renders nothing — a placeholder looks like a measurement, and that's worse than a visible gap.
  • Missing inputs beat wrong confidence. A calculation quietly missing 30% of its inputs is worse than no calculation at all, if it still presents as complete.
  • No database. Chains, IPFS, and generated, versioned snapshots are the entire state — nothing else to trust or distrust.
the occasion

Three real integrations, composed — not three logos stapled on.

Built for ETHOnline 2026 (Sept 4–16), an async hackathon where partner engineers read the repository rather than watch a pitch.

$15,000 · three pools · primary

The Graph

Subgraphs (the standardized module), Substreams (change monitoring), and Subgraph MCP (the agent surface) — composed, not queried once and left alone. Live mainnet data only; mocked datasets don't qualify.

$1,000 · afternoon-scale

Bazantic

A Recipe pairing a Tare resolution endpoint with another sponsor's service, where the final answer depends on both.

$2,000 · optional

Chainlink CRE

A Confidential Workflow — the acting leg. If the effective multiple crosses a private threshold, evaluated inside a TEE, it can trigger a bounded, evidence-gated testnet unwind.

Candidate real fixtures under evaluation — Morpho vaults on Ethereum mainnet, chosen for their allocation depth:

Keyrock USDC — 0x0442…6Bc145 Apyx USDC — 0x0696…1556f0 Hyperithm USDC Apex — 0x0932…179E2F

Kill criterion, stated in advance: if a real three-layer position isn't resolving by day six, monitoring and the acting leg get cut and the resolver ships alone. The resolver is the whole point — everything else exists in service of it.

This page walks from the plain-English idea to the engineering spec behind it, in that order on purpose — the same position resolves either way, only how much of the machinery you want to see changes.
